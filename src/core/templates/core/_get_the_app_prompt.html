{% comment %} One quiet line on the feed, phones only, offering the home screen (S-103). IT IS ONE LINE, and that is the whole design. The email offer one block up was a screen-tall card until the 2026-09-19 walk cut it down to a sentence; a second card would have put the product straight back where it started, with two pieces of chrome between a member and their family's photographs. So this borrows that line's shape exactly: a sentence, a link, and a quiet decline at the end of it. IT NEVER FLASHES. The markup ships `hidden` and only a script can reveal it, because every reason to show it is a browser fact the server does not have: whether this is a phone, whether Backyard is already installed, and whether this person has already said no. A line that appeared and then vanished on every feed load would be worse than no line. THE DISMISSAL IS localStorage, WHICH IS A DEPARTURE. The email prompt beside it is dismissed server-side, on Member.email_prompt_dismissed_at, so it stays dismissed on every device that member signs in on. Doing the same here needs a second column and a migration, and this work item adds neither. localStorage is the honest alternative and its limits are real: saying "not now" on a phone does not silence it on a tablet, and clearing site data brings it back. Both are survivable for a nudge whose whole job is to be ignorable, and the line is per-DEVICE anyway — installing is a thing you do to one phone, so a per-device memory of declining it is not obviously the wrong shape. It is included from feed.html and nowhere else, so it cannot reach the surfaces that must never carry install chrome: the No-Login Link pages (/t/, /e/) and the email web view (/d/) are intermittent token surfaces that plant no worker and link no manifest at all (ADR-002), and an install prompt there would be an invitation to a home-screen icon that opens a login page. {% endcomment %}
