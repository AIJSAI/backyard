{% comment %} The home-screen offer (S-103): one card, at the foot of the screen, once ever. IT REPLACED A LINE ON THE FEED. That line said the same thing in the same words and it was measured on a real phone against the same offer in another of the owner's products: a card that comes up from the bottom edge gets read, and a muted sentence under the composer does not. So the shape changed and the volume did not — it is still one sentence, one way in, one way out, and it is still the quietest thing that can be noticed. IT IS ON EVERY SIGNED-IN PAGE, which is why it is included from base.html rather than from feed.html. Installing is a thing a person decides to do while they are already using the product, not only while they are looking at the composer; the feed-only line reached a member who never scrolled back to the top of it exactly never. NEVER ON A TOKEN SURFACE, AND THAT TAKES TWO MECHANISMS. The No-Login Link pages (/t/, /e/) and the e-mail web view (/d/) plant no worker and link no manifest at all (ADR-002) — they are intermittent surfaces for readers with no session, and an install prompt there would be an invitation to a home-screen icon that opens a login page. A LIVE link is covered by `viewer_on_a_family_link`, which only a view that has RESOLVED a token sets, so a member who happens to be signed in when they tap the link in their mail does not get the card either. A STALE one is covered by the `install_offer` BLOCK, not by that flag: an expired digest link renders Link Expired and a revoked one renders the byte-identical 404, and neither view ever resolved a token, so neither sets the flag. Those pages drop the block instead — as do the other error pages and all four welcome screens, each for its own reason, written where it is dropped. IT NEVER FLASHES. The markup ships `hidden` and only the script reveals it, because every reason to show it is a browser fact the server does not have: whether this is a phone, whether Backyard is already installed, whether this is somebody's in-app browser, and whether this device has been offered it before. ONCE EVER, AND IGNORING IT COUNTS. The mark is written the MOMENT the card appears rather than when it is answered, so a member who scrolls straight past it is never asked twice. That is the whole rule, and it is why there is no "remind me later": a second showing of a nudge this small is worse than never showing it at all. {% endcomment %} {% comment %} A NAMED REGION, not a live region. `aria-live` would announce the card over whatever a screen-reader user was already reading, which is exactly the interruption a nudge this small has not earned; the card is on the page from the first paint and only its `hidden` changes, so there is nothing to announce.
