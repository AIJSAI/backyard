{% comment %} ONE media control, shared by the composer (S-401) and the reply form (S-404). It replaces two stacked native "Choose Files / No file chosen" boxes — the most dated control in the product, on the two screens a family touches most. One picker means one native sheet (Photo Library / Take Photo or Video / Choose File) instead of a form that asks which KIND of thing you are about to share before you have chosen it. NO `capture` attribute, deliberately (owner direction 4): `capture` forces the camera open and hides the photo library, which is the wrong default for a family posting the picture they already took. `accept` is the broad `image/*,video/*` rather than the old explicit MIME list: a phone offers HEIC and .mov whatever we write here, so an explicit list only ever greyed out the pictures somebody actually wanted. The real gate is the server — core/media.py decodes and re-encodes every photo and validates every clip — and `feed_views._split_media` routes each file to the right one of those two gates. `picker_id` keeps the label's `for` unique when two forms share a page. The two ceilings are attributes as well as words. The enhancement script caps what a SECOND pick may add (core/_composer_media.html), and a 20 and a 4 written into that script would be a third copy of a number that already lives in `feed_views._MAX_PHOTOS` / `_MAX_VIDEOS` and in the sentence below — the copy nobody would think to change when the constant moved, and the one that silently drops a photograph when it disagrees. The server stays the single source; these attributes are how it reaches the script. They go on the PICKER rather than into the script because that script is one shared copy bound by field name across the composer and the reply form (S-404): the limits belong to the control, so they travel with the control's markup. {% endcomment %}
