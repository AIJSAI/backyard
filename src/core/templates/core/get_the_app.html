{% include "core/_install_steps.html" %} {% comment %} THE ONE THING THAT SURPRISES PEOPLE. An installed home-screen app on iOS has its own storage container, separate from Safari's, so the session a relative has in Safari right now does not exist inside the icon they just made — they open it and see the sign-in page, which reads as "it did not work". The second line is the case this product actually creates: an admin-issued Sign-In Link (core/recovery.py) is handed over by text, so it is tapped in Messages and opens in Safari. What it does there is set a password (recovery.redeem), and that password is what signs them in inside the app. So the instruction is true for the one member who had no password of their own a minute earlier. {% endcomment %}

Signing In

On an iPhone the installed app has its own sign-in, separate from Safari. Sign in once inside the app, the same way you sign in here.

A Sign-In Link opens in Safari, not in the app. Use it to choose a password, then sign in to the app with that password.
