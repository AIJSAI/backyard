THE EXCEPTION MESSAGE IS NOT PRINTED, and that is deliberate rather than an omission. The default handler passes `{"exception": str(exception)}` into this template, and the refusals raised across the product read like "‹first name› is not in ‹household›" and "You can only post to a pod you belong to" — one names two people to whoever is standing there, the other says an internal noun out loud. The product's own refusals are worded for a screen, not for an exception string, and until they are they stay unread. One plain sentence instead, the same as 404.html and 429.html. Rendered with the request (the default handler passes it), so the context processors run and the page carries the shared chrome and footer.
